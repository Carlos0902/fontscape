# 0.3.0-beta.2 界面终验

在同一台 fontlab-tahoe 测试虚拟机中，通过发布包的真实界面完成以下操作；系统字体写入没有在主机上执行。

- 打开离线操作指引，检查系统状态、包内字体名称/来源摘要、实际字距、按钮启用条件。
- 输入 rollback 但不勾选备份确认：没有请求管理员授权，显示明确的“未执行回滚”提示。
- 输入 rollback 并勾选已保留的完整关机检查点：macOS 显示 osascript 管理员授权弹窗，授权后成功准备回滚快照。完全关机启动后，原始字体哈希及界面启动核验均通过。
- 在界面归档回滚，保留原始备份并清除活动事务。
- 点击“用当前字体生成替换包”，用给定 HanNews 字体和默认 6% em，在 4 CPU / 6 GB 虚拟机中完成整包生成（本次约 12 分钟）。使用应用内置 CPython，不依赖客体系统 Python。生成后面板显示 HanNewsSerif-Medium 与实际 6% 字距。
- 构建进行中尝试从菜单退出：应用显示“字体操作尚未完成”，保留构建任务，点“继续等待”后正常完成。
- 从界面应用新生成的包，包括含空格的 Application Support 路径，输入 apply、勾选备份并完成系统授权。完成提示明确要求完全关机再启动，当前会话没有误报已生效。
- 完全关机启动后，原生文件哈希与新包清单匹配；界面显示 installPrepared / 本次启动字体哈希已核验，实际系统 UI 呈现自定义字体，恢复原始字体入口可用。
- 完整生成和授权操作后，应用仍通过 codesign --verify --deep --strict，未产生破坏签名的字节码缓存。

本轮修正了英文确认词、未确认时的反馈、替换包实际参数显示，以及完成提示被诊断输出遮挡的问题。当前虚拟机保留本次由界面生成并应用的 6% 效果，原始字体备份及先前关机检查点均保留。实体 Mac 与其他系统组合的限制保持不变。

# 0.3.0-beta.1 系统替换验证

环境：Apple Silicon / macOS 26.6.2 (25G83)，VirtualMac2,1。系统卷写入只在原字体实验虚拟机中执行；主机 SIP 与 authenticated-root 保持 enabled。操作前保留了关机克隆。

- 内置 CPython 3.12.16 与 fontTools 4.60.2，离线生成 SFNS 和 32 面 PingFang UI 候选，默认汉字间距 +6% em。
- 抽查中文字体面 0、7、16、31，轮廓与历史 6% 候选一致。新版 Unicode 数据另外识别了少量汉字，按相同 6% em 增加其字宽；非汉字差异检查通过。
- 使用应用内同一份原生 helper：备份并应用 → 完全关机启动 → 两个候选文件哈希及新启动会话核验通过。
- AppKit 普通、粗体、带字重及直接 Core Text 的实际渲染指纹均变化，glyph 数保持。不能据此断言所有界面均覆盖。
- 原生 helper 回滚 → 完全关机启动 → 两个原始字体哈希核验通过；归档后原备份保留、活动事务清除。
- 应用与回滚在同一启动会话内均保持“未核验”，没有把创建快照退出成功当成新启动生效。
- 在虚拟机以 root 实际尝试损坏候选：写入被拒绝，未创建活动事务，当前字体哈希保持原值。
- 清单防护检查通过：拒绝其他版本、Intel、部分/重复目标、路径越界、未审核原始字体哈希、无效摘要、超范围字距、符号链接及空文件。
- 启动核验检查要求新会话、同系统卷、完整预期字体集合与提交阶段；拒绝空清单和错误状态。
- 系统保护检测只接受首行明确 disabled，不能被 Custom Configuration 中局部 disabled 的文字误导。
- 挂载点清理只调用 rmdir；卸载失败时不能递归删除内容，非空目录保留测试通过。
- 包内三个原生可执行文件为 Universal。ZIP 在客体本地解压后可运行内置工具；禁用字节码缓存后，工具运行前后签名核验均通过。

0.3.0-beta.1 发布时，新增界面人工终验因主机锁屏尚未完成；0.3.0-beta.2 已补完，见上文。实体 Mac、FileVault/MDM 组合、Intel 系统替换、其他 macOS 构建以及无法启动时的离线字体修复仍未验证。字体回滚不等于恢复 Apple 密封系统或原系统安全策略。

# 0.2.0-beta.1 验证记录

## 公开应用

实测环境：Apple Silicon，macOS 26.6.2（25G83），主机 SIP 开启。使用用户提供的 HanNewsSerif-Medium.ttf 测试；字体未包含在仓库或下载包中。

- arm64 与 x86_64 Release 构建通过；两个可执行文件均为 Universal。
- ad-hoc 签名通过 `codesign --verify --deep --strict`。这不是 Developer ID 签名或公证。
- GUI 导入与中英文预览通过，原字体文件保持不变。
- 当前用户安装后，独立检查进程可解析相同字体文件。
- 退出、重开后正确恢复选择与安装状态，可以卸载。
- 修复重开后卸载导致进程内注册丢失的问题；卸载后可继续启用与恢复 AppKit 试用。
- 独立探针在仅保留 `/usr/bin:/bin` 的 PATH 下运行，无 Python 运行时依赖。
- 检查报告确认普通、粗体、带字重的 NSFont 请求均命中导入字体；直接 Core Text 保持原值；恢复后快照与试用前一致。
- 无效字体路径返回非零退出状态。
- 结束验证后移除了测试字体的持久注册，安装记录为空。

## 尚未验证

Intel 真机、macOS 14/15 运行、网络下载后的 Gatekeeper 交互、组织管理策略、多字体集合的每个字体面及任意第三方字体均未覆盖。最低部署版本与交叉构建成功不等于这些环境已完成实测。

系统卷研究的结论与公开应用分开记录，见 [高级实验说明](ADVANCED.md)。该限制属于 0.2；0.3 已集成系统替换入口，范围见上文。
