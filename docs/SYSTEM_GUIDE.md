Fontscape 全系统字体替换与恢复（0.3.0-beta.2）

适用范围
只接受 Apple Silicon / macOS 26.6.2 (25G83) 及已核对的原始 SFNS、PingFang UI 字体版本。应用预览仍支持其他平台，但系统替换会拒绝 Intel、其他版本、已被其他工具改写的系统字体或不同系统卷的备份。
实际验证来自隔离虚拟机。实体 Mac 尚未验证，即使预检通过也不代表能可靠启动。不能把此版当作生产 Mac 的稳定换字体工具。

替换的范围
替换 SFNS.ttf 与 PingFangUI.ttc（32 个中文字体面），覆盖通过这些系统字体绘制的中西文 UI；应用自带字体、部分回退字体、Emoji 和其他系统字体不在替换范围。
单个源字体会用于多个请求字重，不产生真正的 Regular/Bold/Light。未覆盖中文使用简体常规字形回退，地区字形及上下文排版可能有差异。

一、先准备独立恢复来源
1. 关闭虚拟机后创建可启动克隆；实体机请先做好可恢复的整机备份，并确认能进入 Recovery。不要只依赖本应用的两个字体备份。
2. 将本文保存到其他设备或外部介质。字体备份保存在 /Library/Application Support/Fontscape/SystemFonts/，不能在移除应用时删除。
3. 确认在目标测试系统内操作。应用的管理员授权针对当前启动系统，不是另一台虚拟机。请勿在主机上点击应用替换包来修改客体。

二、先生成替换包（不需要关闭保护）
1. 导入包含中西文字形的单字体 TrueType TTF。CFF OTF、字体集合以及缺少中文字形的字体暂不能生成系统替换包。
2. 滚动到“全系统字体替换”，点击“刷新状态”，核对设备、25G83 和 arm64。
3. 汉字字距默认为 +6% em，可选 0–10%。这是原始 em 的比例，不是字形拉伸，也不会在上次调整上继续累加。
4. 点击“用当前字体生成替换包”。内置 CPython 与 fontTools 离线生成本机候选，不需要自行安装 Python。通常需数分钟，磁盘需要预留数 GB。
5. 等待显示替换包生成完成。更换源字体或字距后必须重新生成；载入旧包不会自动采用当前滑块值。面板会显示包内实际字距和字体名称或来源哈希。生成失败的目录不是有效替换包。
6. 替换包包含本机 Apple 字体衍生数据，请仅本机实验使用，不要上传或分发。

三、在目标系统的 Recovery 手动准备
系统完整性保护与 authenticated-root 保护系统卷。关闭它们会降低安全性，管理员密码不能代替 Recovery 配置。本应用不会自动执行此步骤，也不会自动改变安全启动策略。
Apple Silicon：正常关机，按住电源键，出现启动选项后选择“选项”进入 Recovery。Tart：先停止目标虚拟机，再以 --recovery 启动它；不要操作主机 Recovery。
在恢复环境的“实用工具 → 终端”中，仅对测试系统手动执行：

csrutil disable
csrutil authenticated-root disable

按提示完成该系统要求的确认/认证并重启。真实设备的本地安全策略、FileVault、MDM 或权限可能阻止操作；此版本未验证这些组合，不提供绕过步骤。
回到目标系统，打开 Fontscape，刷新状态。两项必须明确显示 disabled，且版本及原始字体校验相符。否则停止，不要删除检查条件。

四、备份并应用
1. 再核对目标设备与独立备份。点“备份并应用替换包”。
2. 阅读确认框，勾选已准备独立整机备份/检查点，输入“替换”或 apply。macOS 随后请求管理员授权；授权弹窗会显示“osascript”，这是应用调用 macOS 标准提权入口时显示的名称。密码由系统处理，本应用不保存密码。
3. 引擎先保存原始两个字体并核对 SHA256，记录系统卷 UUID、版本和启动会话，再写入目标文件并创建新的启动快照。操作过程中不要退出或关机。
4. 显示 installPrepared 只表示快照已准备，不代表新字体已启动。完全关机后重新启动；虚拟机需要真正停止 Tart 后重新 run，不能只依赖应用内重启。
5. 再开应用，刷新。看到“本次启动字体哈希已核验”才表示新启动会话加载了预期文件。随后人工检查 Finder、菜单栏、设置、对话框、密码框、图标、中文/英文、标点、窄窗口、不同字号和字重。
6. 若未核验通过，不要归档备份或叠加安装。保留状态和日志，先回滚。

五、正常回滚
1. 在同一系统、同一系统卷内打开应用。保持写入所需的 Recovery 配置，暂时不要重新开启保护。
2. 点击“恢复原始系统字体”，输入“回滚”或 rollback并确认独立备份，再完成管理员授权。
3. 引擎核对原始备份哈希并生成恢复字体的启动快照。显示 rollbackPrepared 后完全关机再启动。
4. 刷新应用，确认“本次启动字体哈希已核验”。只有回滚完成且新启动原始文件匹配时，才能点“归档已验证的回滚”。归档会保留原始备份，不删除它们。
5. 字体文件回滚不等于系统安全保护恢复。只有完全恢复原系统、确认启动正常后，再按独立恢复方案恢复原安全配置。恢复完整虚拟机检查点是已验证的整机恢复方法。

恢复保护
修改过的启动快照不是 Apple 签名密封系统。不要假设把字体拷回去就重新获得有效 SSV。不要在仍使用自制快照时直接执行 authenticated-root enable 并假定必然可启动。
测试虚拟机可恢复修改前的完整关机检查点。实体机恢复完整原始系统后，可在 Recovery 中用 csrutil enable 与 csrutil authenticated-root enable 恢复原配置；如果无法确认密封状态，按 Apple 的恢复/重新安装 macOS 流程恢复系统，再核对两项状态。实体机恢复组合尚未在本项目验证。

异常、无法启动与系统更新
• 显示 needsRecovery 或写入/快照失败：不要把它当成已自动回滚。引擎会尽力恢复已写入文件，但启动快照选择仍可能不明确。保留备份与日志，优先恢复独立整机检查点。
• 无法进入桌面：应用按钮不可用。虚拟机恢复事前的可启动完整关机克隆；实体机进入 Recovery，使用独立备份或 Apple 官方重新安装 macOS 的流程。本文不承诺离线字体拷贝能修复启动链，也不提供未经验证的 Recovery 磁盘写入命令。
• 不要删除、改名或手动修改 SystemFonts 备份目录。不要把另一卷、另一版本的字体备份强行用于当前系统。
• 更新 macOS 前先回滚并确认启动。更新后版本或字体哈希改变，本版会拒绝写入旧替换包。
• 回滚后重新生成新字距或新字体包。每轮事务必须先完成回滚验证和归档；不能把旧候选当成新的原始字体。
